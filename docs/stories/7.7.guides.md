## Story

As a pessoa que aprende o rc pelos guias de uso (instalar, máquina descartável, pack, credenciais, ambiente de dev,
Docker na máquina, agente de código, API local, branch e checkpoint, GPU), I want cada procedimento rodando de verdade
numa VM, com o que falta implementado e o que não se aplica dito com o motivo, so that o roteiro funcione sem
adivinhar nada.

## Acceptance Criteria

1. **Cada guia** é uma pasta `examples/guides/<pasta>/run.sh` (as provas do guia numa VM de verdade, saindo com o
   número de falhas) e um `README.md` que explica cada passo.
2. **Cada tema de referência** tem destino em `examples/guides/reference/`: etapa do `run.sh` com prova, outra pasta,
   ou o motivo de não se aplicar.
3. **O que os guias usam e o rc não tinha, implementado**, com teste de unidade, e2e numa VM real e defeito plantado:
   - `machine run` preso ao CLI;
   - `/dev/stdin` e `/dev/fd` no guest;
   - vsock sem meio-fechamento;
   - `--user`, volume de disco, `docker_socket`, segredos, agente SSH, prune, `data-dir`;
   - corpos alternativos da API, SSE por linha, campo desconhecido recusado;
   - ICMP pelo gateway, `--nested`, falha do vmm na hora;
   - `--expose-socket`/`--mount-socket`, faixa de portas, tabela de sinais, `gpu_vram` sem `gpu`;
   - `:staged` + `rc machine sync`.
4. **O que não se aplica é recusado com o motivo**, sem criar nada (`--cuda`, `nested` no arquivo, flags inexistentes).
5. Runbook com uma seção por recurso novo e o passo correspondente no `scripts/runbook.sh`, verde.
6. Gate de cobertura verde (90% total, 100% domain, catraca do guest subindo, nunca descendo).

## Dev Notes

- O runner das pastas é `scripts/guides.sh` (`task guides DIRS=...`); `lib.sh` concentra o que todo `run.sh` precisa
  (cabeçalho do `ls`, processo do vmm, `data-dir`, lista vazia).
- Limites de fundo, declarados onde aparecem: não há snapshot de RAM (checkpoint é de disco, via `branch`), não há
  CUDA, não há TSI (toda rede é virtio-net pelo gateway).
- Medido no virtio-fs da libkrun no macOS: arquivo novo que o guest cria num volume do host fica 0600 (diretório 0700),
  com o modo do guest no xattr `user.containers.override_stat`. O sync do staged aplica esse modo no host.
