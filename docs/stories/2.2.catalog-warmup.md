## Story

As a usuário da API, I want as linguagens começarem quentes, so that a primeira execução não pague JIT nem cache frio.

## Acceptance Criteria

1. `languages.yaml` embutido: `name, image, cpus, memory_mib, warmup` para as linguagens do executor que têm imagem oficial.
2. O warmup roda em chroot na VM de build e fica gravado no ext4.
3. Python: `compileall` da stdlib. Java: `java -Xshare:dump`. Go: build de um hello com `GOCACHE` na imagem. Node: `NODE_COMPILE_CACHE`.
4. Medição antes/depois para Python e Java, registrada na story.

## Tasks / Subtasks

- [x] Schema e loader do catálogo, com validação (AC 1)
- [x] Warmups por família (AC 2, 3)
- [x] Medir e registrar (AC 4)

## Dev Notes

- A imagem oficial do Python **não** traz `.pyc` (o spike gerou +21 MB com `compileall`).
- O root é read-only. Cache que precisa de escrita em tempo de execução (GOCACHE) é copiado do caminho aquecido da imagem para `/tmp` no `start.sh`, ou usado em modo leitura quando a ferramenta permitir.
- Recursos são teto contra abuso: a memória é elástica (RAM de 256 a 2048 MiB não muda o boot; footprint parado é 44 MB).
