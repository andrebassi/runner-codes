## Story

As a pessoa ou agente trabalhando numa máquina persistente, I want um terminal interativo de verdade nela, so that eu
use o shell como numa máquina local (Ctrl+C, histórico, editores, tamanho da janela) — como o `smolvm machine shell`.

## Acceptance Criteria

1. `rc machine shell --name N [-e K=V] [-w DIR] [-- CMD]` abre um PTY no guest: o programa vê um TTY e o tamanho da
   janela do host; o resize da janela chega ao guest.
2. Ctrl+C interrompe só o comando em primeiro plano; o shell e a máquina continuam.
3. O rc do `rc` é o do programa (`exit 4` → 4). Fechar o terminal mata o programa no guest; a máquina continua ligada.
4. Sem comando, abre `bash` se a imagem tiver, senão `sh`.
5. O que o shell grava persiste como no `exec` (mesma raiz e `/workspace`).
6. Runbook com o passo novo, executado pelo `task runbook`.

## Dev Notes

- A sessão usa a mesma conexão vsock do `exec`; depois do frame inicial ela vira um canal de frames nos dois sentidos.
- Bytes do terminal vão como `[]byte` (base64 no JSON): numa string JSON, byte de controle ou UTF-8 partido viraria
  U+FFFD.
- Fim do stdin do host (pipe) manda Ctrl+D ao terminal, para o shell sair em vez de esperar para sempre.
