## Story

As a host, I want o guest-runner atual rodando como o processo de exec da libkrun, so that o protocolo vsock existente funcione sem o handshake do Firecracker.

## Acceptance Criteria

1. `pkg/guest` vai para `internal/guest`, compila em `GOOS=linux` e não é importado por código de host.
2. `start.sh` (injetado na imagem) monta tmpfs em `/tmp` (256 MiB) e executa `/opt/runner/guest guest --port 5000`.
3. `internal/adapters/guestproto.Client.Run(ctx, sock, job)` faz o round trip com o framing atual e respeita o deadline do ctx.
4. `WaitReady(ctx, sock)` tenta a cada 1 ms até ter resposta de um ping (job `sh` `true`).
5. Um job Python devolve stdout e exit code corretos pela VM real (e2e).

## Dev Notes

- Protocolo: 4 bytes BE de tamanho + JSON `Job{trace_id,lang,code,files,stdin,timeout}` → `Result{status,stdout,stderr,exception,executionTime,exit_code,error}` (`pkg/guest/types.go`).
- Conectar no socket **não** prova que o guest escuta: a libkrun cria o socket antes. Só a resposta prova.
- O guest atual usa `mdlayher/vsock` para escutar. Dentro da VM isso funciona sem mudança (provado no spike).
- O root é read-only: toda escrita do executor vai para `/tmp` (tmpfs). HOME pode continuar `/root` só para leitura; compiladores que gravam cache usam `/tmp` via env (`GOCACHE=/tmp/go-cache` copiado do cache aquecido na story 2.2).
