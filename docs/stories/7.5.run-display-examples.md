## Story

As a pessoa que quer rodar aplicações reais no rc, I want exemplos prontos com comandos curtos (uma VM efêmera, imagem
local, desktop no navegador), so that cada cenário comum funcione sem montar tudo do zero.

## Acceptance Criteria

1. `rc machine run`:
   - cria, liga e roda o comando do `--` (ou o `cmd` do `runner.code`, ou um shell com `-t`);
   - devolve o rc do comando;
   - apaga a máquina no fim, inclusive no Ctrl+C (rc 130);
   - `-d` deixa ligada com o comando como workload;
   - `-i` repassa o stdin; sem `-i` o stdin não é lido.
2. `--image` aceita caminho local (tar do `docker save`, tar OCI, diretório OCI layout) e `-` (stdin, guardado por
   sha256). Arquitetura diferente da do host é recusada.
3. `-s` (sinônimo de `-f`), `--mem` e `--storage` são sinônimos das flags do rc.
4. Porta publicada TCP entra pelo guest (op `dial` no vsock) e alcança servidor que escuta só em `127.0.0.1`.
5. `--display LxA` / `display` no `runner.code`:
   - tela virtio-gpu servida no navegador (`127.0.0.1:6080`), com teclado e mouse por virtio-input;
   - cada tecla chega num pacote próprio, com Ctrl, Shift, Alt e Meta sincronizados.
6. 8 exemplos em `examples/`, cada um testado numa VM real, com o que foi medido no `examples/README.md`.
7. Runbook com os passos novos (8e–8h), executados pelo `task runbook`.

## Dev Notes

- A libkrun chama os callbacks do display e da entrada a partir de uma thread dela. O `purego.NewCallback` funciona
  sem cgo, e o spike provou isso antes de qualquer outra parte (`display: create` no log).
- O `Rutabaga2D` só é usado como componente padrão, exclusivo. Por isso o patch troca o componente inteiro, e a VM com
  tela perde o Venus.
- O patch roda com `sed` com lookahead (as duas linhas iguais do builder e do fallback) e um `grep` que derruba o build
  se a troca não acontecer exatamente uma vez.
