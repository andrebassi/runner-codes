## Story

As a quem roda carga de IA no runner, I want que a VM enxergue a GPU do host por Vulkan, so that modelos
(llama.cpp) usem a GPU em vez de só CPU.

## Acceptance Criteria

1. `.#krun` no macOS compila a libkrun com `GPU=1` sobre um virglrenderer com Venus (fork `slp` 0.10.4e-krunkit) e
   MoltenVK, tudo pelo Nix.
2. GPU é opt-in: `gpu: true` (e `gpu_vram_mib`) por stack no catálogo, `rc run --gpu`, campo `gpu` na API. Stack sem
   GPU recusa o pedido com 400. Sem pedido, nada muda (mesma spec de VM, mesmo pool).
3. Com GPU, o `vmm` chama `krun_set_gpu_options2(ctx, VENUS|NO_VIRGL, vram)` e o guest vê o device: `vulkaninfo`
   mostra `Virtio-GPU Venus`.
4. Stack `llama` (llama.cpp com backend Vulkan) roda um modelo pequeno com GPU; o e2e compara com a mesma execução
   sem GPU.
5. VM com GPU sobe a frio (fora do pool) e com limite próprio de simultâneas.
6. Documentado: CUDA não suportado (exige host Linux + NVIDIA); Linux com Venus declarado e não testado; isolamento
   de GPU é por processo, não fronteira de VM.

## Dev Notes

- `VIRGLRENDERER_VENUS` = 1<<6, `VIRGLRENDERER_NO_VIRGL` = 1<<7 (`include/libkrun.h`). O krunkit no macOS usa
  Venus sem o virgl (OpenGL), porque o MoltenVK só traduz Vulkan.
- O `shm_size` é a janela de memória do host que o guest vê como VRAM; reserva endereço virtual, não RAM física.
- Guest: Fedora 43 com o Mesa do COPR `slp/mesa-libkrun-vulkan` (patch de 16 KiB). O plano inicial era Alpine com
  `mesa-vulkan-virtio`, descartado depois de medido (Debug Log).

### Debug Log References

- virglrenderer do nixpkgs sai com `-Dvenus=false` no macOS → derivação própria do fork `slp` 0.10.4e-krunkit; o
  hook de meson do Nix liga features `auto` e o configure exigia libdrm → `-Ddrm=disabled`.
- Alpine edge (`mesa-vulkan-virtio`): `/dev/dri` aparecia, mas `vkCreateInstance` falhava com
  `ERROR_OUT_OF_HOST_MEMORY` e a libkrun registrava `Error adding memory map: MemoryMap`. Causa: o Mesa aloca blobs
  em 4 KiB (página do guest) e o `hv_vm_map` exige 16 KiB. Aumentar a VRAM (8 e 16 GiB) não mudou nada. A saída é
  o Mesa do COPR `slp/mesa-libkrun-vulkan`, que alinha a 16 KiB (`0001-virtio-vulkan-force-16k-alignment...patch`).
- O `llama-cpp` do Fedora não tem backend Vulkan → compilado no warmup; faltou `spirv-headers-devel`; o
  `cmake --install` tentava instalar testes não compilados → binários estáticos copiados com `install`.
