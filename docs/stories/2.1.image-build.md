## Story

As a operador, I want `runner.code image build --lang <l>`, so that a imagem da linguagem seja gerada sem Docker e sem root.

## Acceptance Criteria

1. Pull com go-containerregistry para `linux/<arch do host>` e achatamento com `mutate.Extract`.
2. VM de build (Alpine 3.22.6, sha256 conferido, e2fsprogs + GNU tar) extrai em tmpfs, injeta o guest e o `start.sh` e roda `mkfs.ext4 -d`.
3. Cache pelo digest: um segundo build do mesmo digest só confere o cache, sem refazer.
4. Tamanho do disco = usado × 1,25 + 32 MiB.
5. Resultado em `<cache>/images/<lang>-<digest12>.ext4`, com um symlink `<lang>.ext4` apontando para o atual.

## Dev Notes

- O APFS não diferencia maiúsculas de minúsculas, e o e2fsprogs do brew não lê tar. Por isso a extração e o mkfs acontecem **dentro** da VM de build (Linux, tmpfs).
- A VM de build é código confiável: é a única com TSI (rede), para o `apk add` do bootstrap.
- Comando para a VM de build vai por arquivo (`/work/build.sh`), nunca por argv com espaço.
- O guest (`linux/<arch>`) vem do próprio binário do host via `go:embed` (story 4.1 gera o artefato); até lá, um build `GOOS=linux` no Taskfile.
- Spike de referência: `spike/ocitar/main.go` (2,7 s para o python:3.12-alpine) e `work/build.sh` registrado na architecture.
