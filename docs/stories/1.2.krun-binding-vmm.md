## Story

As a serviço, I want lançar uma VM por spawn de `rc vmm --spec`, so that cada VM seja um processo descartável.

## Acceptance Criteria

1. `internal/adapters/krun` carrega a libkrun por purego e expõe as chamadas usadas, atrás de uma interface `krunAPI` (fake em teste).
2. `Spec` (JSON): cpus, memória, disco root, socket vsock, exec, console. `Configure(api, spec)` monta a sequência de chamadas e é testada só com fake.
3. Rede desligada: `disable_implicit_vsock` + `add_vsock(0)`. Um teste afirma que TSI nunca é ligado sem `Network=true`.
4. Linux: `Pdeathsig`. macOS: pipe de vigia. Matar o pai mata a VM (e2e).
5. `Launcher.Start(spec)` devolve o processo com `Setpgid`; `Kill` manda SIGKILL ao grupo.

## Dev Notes

- Sequência validada no spike (`spike/krunboot/main.go`): `create_ctx` → `set_vm_config` → `add_disk2("root", path, 0 /*RAW*/, true)` → `set_root_disk_remount("/dev/vda","ext4","ro")` → `disable_implicit_vsock` → `add_vsock(ctx, 0)` → `add_vsock_port2(ctx, 5000, sock, true)` → `set_console_output` → `set_exec("/opt/runner/start.sh", argv, envp)` → `start_enter`.
- `start_enter` só volta em erro. No sucesso o processo sai com o código do workload. Os buffers de argv/envp precisam ficar vivos (variável de pacote).
- A libkrun carrega a libkrunfw por nome: no mac o filho precisa de `DYLD_LIBRARY_PATH=/opt/homebrew/lib`.
- **argv com espaço chega quebrado** (vai pela cmdline do kernel). Nunca passar script por argv.
- **Spawn, nunca fork:** fork de processo multi-thread é morto pelo HVF em ~2 s.
- O binário precisa do entitlement `com.apple.security.hypervisor` (assinatura ad-hoc basta; `task sign`).
- Pipe de vigia: o pai passa o fd 3 (lado de leitura de um pipe); o `vmm` abre um goroutine que lê até EOF e chama `os.Exit(137)`.
